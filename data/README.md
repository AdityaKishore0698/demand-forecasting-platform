# Data

## The real dataset is NOT included

- **Dataset:** *Rossmann Store Sales* (daily store sales for 1,115 drugstores, 2013 – mid 2015)
- **Source:** Kaggle — <https://www.kaggle.com/c/rossmann-store-sales>
- **Ownership / terms:** it is a third-party dataset. It is not part of this project, this repository does not license it, and its redistribution terms have not been verified — so **no raw data, and no file derived from it, is published here.** Get it from the source above and follow its terms.
- The **code, configuration, tests and documentation** in this repository are my own independent implementation. The **synthetic demo data** (below) is generated by this project's code and is not Rossmann data.

The results quoted in the README were measured on an adapted version of that dataset (columns renamed, history ending 2015-06-19, forecast window 2015-06-20 → 2015-07-31). You do **not** need the real data to run the app.

## Run without any real data (demo mode)

```bash
make demo         # generate SYNTHETIC data into data/synthetic/ and train the demo bundle -> artifacts/demo/
make api          # serves artifacts/demo by default; the UI shows "Demo mode — using synthetic data"
```

The synthetic dataset comes entirely from a random-number generator (`src/data/synthetic.py`). It mimics the *structure* the pipeline must handle — weekly rhythm, closed days, promotions, holidays, school closures, stores with gaps in their history, a training-only column — so the whole system can be demonstrated. Any metric computed on it is a demonstration value, not a result.

## Using the real dataset locally

Place three CSV files in `data/raw/` (git-ignored) with the schema below, then run `make train`; the API will serve the resulting `artifacts/` bundle instead of the demo bundle.

| File | Rows | Columns (as the code expects them) |
|---|---|---|
| `orders_train.csv` | store × day of history | `HubID, Weekday, Date, OrderVolume, AppSessions, IsOpen, PromoActive, RegionalHoliday, SchoolClosureFlag` |
| `orders_test.csv` | store × day of the future window (schedule only, no demand) | `Id, HubID, Weekday, Date, IsOpen, PromoActive, RegionalHoliday, SchoolClosureFlag` |
| `hub_metadata.csv` | one per store | `HubID, HubFormat, AssortmentTier, CompetitorDistance, CompetitorOpenSinceMonth, CompetitorOpenSinceYear, LoyaltyProgram, LoyaltyProgramSinceWeek, LoyaltyProgramSinceYear, LoyaltyProgramInterval` |

The code uses generic names. The Rossmann files use different ones; the expected correspondence (assumed from the column meanings — **not verified against the original files here**) is:

| This project | Rossmann Store Sales |
|---|---|
| `HubID` | `Store` |
| `Weekday` (1 = Mon … 7 = Sun) | `DayOfWeek` |
| `OrderVolume` | `Sales` |
| `AppSessions` (train-only, unused by the model) | `Customers` |
| `IsOpen` | `Open` |
| `PromoActive` | `Promo` |
| `RegionalHoliday` (0/1) | `StateHoliday` (non-zero → 1) |
| `SchoolClosureFlag` | `SchoolHoliday` |
| `HubFormat` / `AssortmentTier` | `StoreType` / `Assortment` (letters → integers) |
| `CompetitorDistance`, `CompetitorOpenSince*` | `CompetitionDistance`, `CompetitionOpenSince*` |
| `LoyaltyProgram*` | `Promo2*` (`PromoInterval` → `LoyaltyProgramInterval`) |

The pipeline needs history up to the last known day plus a schedule for the following 42 days for every store; it validates this before training and fails with a specific message otherwise (`src/data/loaders.py`).
